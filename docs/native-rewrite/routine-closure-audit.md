# Routine closure audit

Reference: `household-os` commit `4a528c96caf41515a70291ccecbba9d7b35e3349`. No hosted data or production execution.

The active closure implementation is `private.apply_routine_closure` from `20260830220000_preserve_reschedule_on_rebuild.sql`, not the original routine-engine implementation. Its test-only excerpt is kept verbatim in `tests/database/legacy-routine-edits/closure.sql`. Public complete/skip/reschedule wrappers come from `20260809210000_routine_engine.sql`; the receipt table includes the later nullable occurrence reference and `ON DELETE SET NULL (occurrence_id)` amendment. Fixture grants restrict the private helper and public wrappers; supporting data already uses the audited creation/edit/notification fixtures.

The engine authorizes household membership, takes a household/idempotency advisory lock, then locks the target occurrence, routine and preview. It only changes the current open occurrence. Completion stores an append-only completion row; completion and skip retain closed occurrences and advance the current/preview window. Rescheduling preserves occurrence identity and original due-date anchor, replaces its due date, updates the existing opted-in reminder candidate and emits the audited partner notice. Reminder candidate identity is reused; a cancelled row is reset to pending with the new date rather than retained as a separate cancelled record.

Legacy retry receipts are household/key scoped and do not bind actor or full request. If the target is deleted by a later definition rebuild, legacy replay can return an accessible receipt by key. Native wrappers therefore need their own immutable actor/household/operation receipt, exact target/version checks, current membership checks before replay and server-generated legacy keys. Existing native completion must be exercised against this full engine before its concurrency and migration behavior are considered verified.

Three local database cases verify complete/skip succession and exact replay, reschedule identity/anchor/reminder-date/partner-notice behavior, and foreign-member/preview denial without partial state. These tests use the real audited function bodies, not closure mocks. They do not prove native skip/reschedule, accepted takeover, offline completion races, full migration compatibility or delivered notifications. Those remain required work.
