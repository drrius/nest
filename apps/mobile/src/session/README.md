# Native household identity

Apple sign-in exchanges a nonce-bound identity token through pinned Supabase SDK 2.116.0. Tokens use SecureStore with `WHEN_UNLOCKED_THIS_DEVICE_ONLY`; there is no plaintext fallback. The UI receives only the API-verified member, never session credentials. Auth refresh runs while active; foreground and token changes recheck membership. Stale identity responses cannot replace a newer account, and logout hides identity before revocation finishes. Nonmembers receive recovery guidance rather than household access.

Configuration uses the three public values in `apps/mobile/.env.example`. URLs must be HTTPS origins; development permits localhost HTTP only. Never put server secrets in these variables. No provider settings or production data are changed by this source.

Local verification: fourteen Effect/SDK tests cover bearer identity, mismatched stored actors, denial/errors, stale responses, logout/hydration races, refresh visibility and pinned-SDK credential removal despite unavailable revocation, storage read/delete failures and cleanup retries. iOS Metro export and generated Apple entitlement pass. These do not verify Keychain behavior, Apple UI, native refresh or account identity continuity.

Use an isolated configured API/backend and an installed iPhone development build. Provider/account changes are not automated. Test cold restore, canceled sign-in, nonmember denial, expired refresh, SecureStore write/delete failures, logout offline and app restart. The authenticated Today chore route now connects this session to durable replay; see `../chores/README.md` for its precise limits. Cold-start membership verification still requires connectivity. The four-tab design preview remains fictional and development-only.

Audited reference: legacy `auth-apple.ts`, `complete-id-token-sign-in.ts`, `resolve-session.ts` and `session-loader.ts` at `4a528c96caf41515a70291ccecbba9d7b35e3349`. Retained the explicit membership boundary and superseded-response protection; did not copy AsyncStorage persistence or cookie-bound services. SDK logout behavior was checked in the installed version and tested rather than assumed.

Warm foreground revalidation keeps the same verified member in memory through transient network/SDK failures and marks it offline, so loaded chores remain usable. It never restores a different actor, a definitively denied member or a logged-out identity. Cold-start offline access still has no persisted authorization grant.
