# Native grocery checking

This gated additive migration extends the existing `grocery_items` with `native_checked` and a monotonically increasing `native_version`. It does not create a second grocery database, finish a shopping session, infer an expense, or rewrite legacy state/history. Existing active/claimed records start unchecked; purchased/removed records remain historical and are unavailable to the native check command. Production application and the old-writer cutover remain separate owner gates.

Audited reference: Household OS commit `4a528c96caf41515a70291ccecbba9d7b35e3349`, migration `20260811180000_meals_groceries.sql`, specifically grocery row states/constraints, shopping-session references, RLS and column-level grants. Its existing restricted insert/update grants do not grant clients access to the new writable columns. The fixture deliberately reproduces only relevant row fields, membership and grants; it does not prove the complete legacy shopping/meal/financial closure.

`nest_set_grocery_checked` authorizes current actor/household membership before reading any receipt, locks membership against deletion, validates parameters and serializes the operation identity. An exact retry returns the stored result; changing target/expected version/checked value under the same operation fails. The item transition and receipt insertion are atomic. Versions travel as strings to avoid JavaScript bigint rounding.

An action matching canonical checked state is compatible and records a no-op receipt, even if its expected version is old. An opposite action from an old version conflicts. A current opposite action changes the state once. All item updates, including legacy description/schedule-state updates, advance the native version through a trigger. Checking preserves `state`, claimed-session ID and purchase/removal timestamps. An internal helper has no public facade or authenticated EXECUTE grant and independently checks identity/membership.

The receipt's original result is immutable even if the item later changes; after replay, clients must fetch an authoritative bounded snapshot rather than treating old receipts as current truth. UI/AI adapters still need to map the response into the outbox receipt contract and offer explicit conflict recovery. No clock-based last-write-wins rule is used.

Locally verified with disposable PostgreSQL 18.6: 12 tests for retry identity, compatible checks, incompatible/ABA intents, changed-payload rejection, removed/purchased/missing targets, legacy edits, column grants, tenant/receipt isolation, transaction rollback, concurrent operations, legacy claim preservation, revoked membership and helper denial. Supabase security advisors against the fixture Unix socket reported no issues. No production query or mutation ran. The cluster runner is the unchanged audited PR #4 harness.

Remaining: full-schema migration rehearsal and advisors, native/UI/API/AI command integration, online create/edit/remove operations, snapshot pagination, two-device airplane-mode and process-kill journeys, and gating incompatible legacy writers before cutover. This server command does not complete the grocery vertical slice by itself.
