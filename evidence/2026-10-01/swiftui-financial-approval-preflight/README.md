# Fresh online preflight for existing financial approvals

Expense, refund, correction, settlement and recurring creation/update private approval decisions now read the current exact authorized proposal before creating a new local journal entry. Operation, approval, actor/household and payload matching must succeed; the result must still be pending and unexpired. Both confirmation and decline need this fresh read. Account generation/SQLite lease checks remain before and after journaling. Failed/offline/expired/substituted/denied reads cannot create a new saved money decision or send a POST.

Already staged decisions remain unchanged. Receipt-first explicit retry and owner-locked expiry recovery preserve lost replies; loading does not send or discard financial intent. Existing expiry tests now stage while the proposal is valid and then expire it, so they continue to establish recovery of an already-staged decision rather than permitting new expired initiation.

Six new native test methods are written: five command-family matrices cover confirm/decline crossed with offline, expired, substituted operation, foreign actor and denied proposal; one delayed expense read covers sign-out and member switch. Existing ten lost-reply/expiry recovery tests remain. Tests use injected HTTP and real temporary SQLite, not hosted accounts or a live provider. Native execution is pending; local source budgets/diff checks pass. Ordinary money entry staging remains a separate audited gap and must receive its own fresh-online/domain preflight. No new API, migration, purchase, deployment, beta, merge or production action occurs in this fix.
