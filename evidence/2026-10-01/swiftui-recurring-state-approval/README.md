# SwiftUI recurring pause/cancel approvals

Current feature work adds typed private pause/cancel approval reads and exact decisions, fresh rule/revision review, native confirmation/decline, assistant result links and scoped SQLite recovery. Opening a card never executes it. New decisions require online preflight; money stays online-only. A lost response retains the exact decision and reviewed rule across restart. Retry first reads its authoritative outcome, and changed rules prevent another approval write. Unresolved intent cannot be overwritten or discarded. Saved decisions are exposed in the approval list. Account generation and lease checks fence private results and writes.

The owner-only expiry RPC is extended by additive migration `20261001093000_native_recurring_state_approval_expiry.sql` to accept only the additional pause/cancel command identities. It retains the approval lock and makes no decision, rule or ledger mutation. This migration has **not** been applied to a hosted project; the stable test API also predates the new expiry command allowlist. Hosted expired-decision recovery therefore remains a required test/deployment prerequisite. Production is untouched.

Local meaningful verification:14 cases passed, zero failures/skips, against strict Effect wire schemas, actual isolated PostgreSQL/PostgREST, API and registered AI SDK tool execution. This includes substituted identities, command-bound expiry, owner/partner denial, consumption locking, pause/cancel unused/denied/consumed outcomes, lost approval/decline replies, rule supersession and financial-event count remaining zero. Commands used the disposable fixture bins `/tmp/nest-postgres/usr/bin` and `/tmp/nest-postgrest/postgrest`; no hosted database URL or provider call was used. Source budgets and diff checks pass. Contracts/API typechecks and current-head CI are recorded when completed.

Three new Foundation and six signed-native cases are written for canonical links/receipts, private restart/expiry evidence, explicit approve/decline, dropped replies, offline/changed preflight, consumed-during-expiry recovery and delayed sign-out/member switching. They are **not yet executed**. Owned rendered confirmation/recovery/navigation, hosted migration/API behavior, live provider and both-phone acceptance remain unverified. No new build, purchase, deployment, merge or production action occurred.
