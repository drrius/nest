# Narrow Nest privileged-entry-point review

Reviewed4 October2026 against the actual hosted definitions of all21 `public.nest_*` functions included in the authenticated security-definer advisor group. This is an access-control review of these entry points and their delegated guards, not a certification of all81 public functions or140 private definers.

## Guard trace

| Entry points                                                                                    | Actual boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `nest_save_settlement`, `nest_execute_settlement`                                               | Delegate to `private.nest_record_settlement`, which requires a nonnull authenticated actor and locked membership in the requested household before journal/ledger access. Receipt keys bind actor/household/operation. Payer and recipient must belong to that household; the reviewed outstanding balance is revalidated under the ledger lock. Approved execution consumes an owner-only exact unexpired command/payload/operation approval. Direct Save represents explicit UI confirmation, not an AI bypass |
| `nest_save_renewal`, `nest_remove_renewal`                                                      | Delegate to `private.nest_change_renewal`, which checks authenticated household membership before any access/write. Existing rows, responsible-member and recurring-rule references are household bound; operation receipts are actor/household/operation bound and revision checked                                                                                                                                                                                                                             |
| `nest_read_renewal`, `nest_list_renewals`, `nest_calendar_renewals`                             | Require current membership in the requested household before querying rows with that exact household predicate. Calendar projection reads only Nest renewals, not private EventKit details                                                                                                                                                                                                                                                                                                                       |
| `nest_read_renewal_operation`, `nest_cancel_renewal_operation`                                  | `private.nest_recover_renewal` checks membership before access/cancellation. Both receipt and cancellation use the authenticated actor plus requested household/operation                                                                                                                                                                                                                                                                                                                                        |
| `nest_save_renewal_reminder`, `nest_read_renewal_reminder`                                      | Check current household membership first. Item/reminder queries use the household; writes require both reviewed revisions and validate each recipient's membership. Recipient preference authority is not accepted in the command                                                                                                                                                                                                                                                                                |
| `nest_read_renewal_reminder_operation`, `nest_cancel_renewal_reminder_operation`                | `private.nest_recover_renewal_reminder` enforces current membership and actor/household/operation receipt/cancellation scope                                                                                                                                                                                                                                                                                                                                                                                     |
| `nest_save_push_device`, `nest_read_push_device_operation`, `nest_cancel_push_device_operation` | Enrollment and operation reads/cancellation require requested-household membership and actor-bound identities. Enrollment additionally fences cancelled operations and revoked sessions. Its delegated device writer checks membership, ownership/revision and actor-bound exact receipts before token changes                                                                                                                                                                                                   |
| `nest_revoke_push_session`, `nest_revoke_previous_push_session`                                 | Deliberately available after household removal so a member can disable their old device. Require an authenticated session; delegated revocation inserts only `(auth.uid(), session)` and changes devices only for that actor/session. A guessed other actor's session cannot revoke their devices                                                                                                                                                                                                                |
| `nest_convert_legacy_renewal`                                                                   | Requires current requested-household membership first. Locks the household-bound legacy commitment and compares the exact reviewed source hash; existing conversion receipts bind actor/operation/hash. A recurring link must already have explicit native adoption. Saving goes through the guarded native renewal command                                                                                                                                                                                      |
| `nest_cancel_routine_creation`                                                                  | Requires nonnull actor/current requested-household membership before receipt or cancellation access. Actor/household/operation/hash bind the outcome; an existing committed creation returns its original receipt instead of deleting it                                                                                                                                                                                                                                                                         |
| `nest_financial_approval_expiry`                                                                | `private.nest_owned_action` requires the approval's authenticated owner and current membership before returning it. The public reader additionally binds household, invocation, command/version and allowed command family; a consumed approval never attests unused                                                                                                                                                                                                                                             |

The actual serializers and validators reached by these paths accept explicitly passed rows/fields and do not fetch another actor's private data. This trace does not extend to every deeper legacy financial implementation, worker or externally callable legacy entry point.

## Definition and behavioral evidence

[Compiled definition comparison](native-definition-match.json) matches all21 public entry-point bodies plus13 directly referenced private helper bodies against a fresh disposable local schema compiled from54 audited legacy and248 current Nest migrations. All34 bodies match exactly after trimming only surrounding body whitespace. Function moves/renames and five later conflict-code rewrites are therefore accounted for by real PostgreSQL execution. The first regex-only source comparison could not account for those transformations and was not accepted as drift or parity proof. Full definition/header hashes and all302 migration hashes are retained. Ownership, complete ACL parity, simulated Auth/Storage and excluded pg_net are explicit limits.

Forty-one focused existing PostgreSQL tests pass, zero failures/skips, in11451.546096ms. These exercise native settlement/approval ownership, malformed and stale financial authority, transactional rollback/centime sequences, renewal/reminder tenant isolation, private receipts, cancellation/races, push revocation ownership after household removal, routine creation cancellation and owner-bound locked expiry. They run actual functions in disposable clusters; some fixtures load a bounded migration subset rather than the full chain. These are database tests, not native/device or provider verification.

The exact focused command was:

```sh
NEST_TEST_PG_BIN=/tmp/nest-postgres/usr/bin node --test --test-concurrency=2 \
  tests/database/native-settlement.test.mjs \
  tests/database/settlement-approval.test.mjs \
  tests/database/renewals.test.mjs \
  tests/database/renewal-reminder-storage.test.mjs \

```

[Hosted read probes](native-read-probes.json) execute five read-only RPCs for both fictional members, outsider, anonymous and an unjoined household:25 cases pass (10 HTTP200, five401, ten403). The member receipts remain actor scoped and unresolved for the fresh unused operation; no populated private receipt isolation is claimed by those probes. The first attempt stopped at an expired independent JWT; only verifier sessions were refreshed, leaving the native Keychain session unchanged. No mutation, revocation, enrollment, worker, inference or production function was invoked on the host.

The21 Nest advisor findings are investigated with this bounded guard/body/behavior evidence; their authenticated execution is needed for supported commands. The advisor still reports them. No grant was loosened, warning suppressed or conversation resolved to clear a gate. The60 legacy public warnings, the broader private callable/helper surface, signup/provider decisions, complete current hosted Auth/Storage behavior, external writers and full M9 acceptance remain open.
