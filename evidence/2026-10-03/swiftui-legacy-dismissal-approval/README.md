The existing registered AI tool proposes only a known retained draft ID. The server binds its original rule, raw review token, owner and operation; proposal output grants no authority. Canonical assistant results and the owner's pending-approval list open fresh native private context. Explicit confirmation requires exact current retained terms, original raw token, unexpired private approval and a verified member. Expired or changed proposals can still be explicitly declined. If the old draft context becomes inaccessible, only its separately verified owner-bound private proposal may be declined; no financial confirmation can use missing terms.

SQLite retains the exact original decision, reviewed context, owner and household before dispatch. Loading/foregrounding checks results only; it never sends a decision. Explicit retry checks the private receipt first. A raw fingerprint can change and revert, so mismatch or local expiry never silently retires consent. Explicit withdrawal persists before sending the negative decision, including across failed replies and restart. A prior recorded dismissal wins truthfully. Only consumed/denied server outcomes allow cleanup, and complete terminal receipts cannot regress. This path uses existing serialized withdrawal; it requires no new expiry RPC or migration.
